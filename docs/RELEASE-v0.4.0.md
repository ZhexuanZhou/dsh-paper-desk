# v0.4.0

## 用户可见变化

- 采用阅读优先布局：文献列表默认收起，助读、批注、笔记共用右侧面板；正文与 AI 回答提高字号，强调色改为低饱和灰绿。
- 搜索摘要、笔记和已提取正文时，界面与 Agent 使用同一查询逻辑；输入搜索词会展开结果列表，并显示命中片段。
- 每条 AI 回答分别展示自己的引用，包括已保存的历史回答。点击引用可核对原页图和提取文本，再跳转阅读器。
- 助读支持选择最多三页 PDF 原图随问题发送；选区提问附对应原页。普通问答保持文本输入。图片生成或模型请求失败会保留问题并显示错误。
- 新增研究专题：研究问题、关联论文与专题笔记保存在库内普通文件。讨论复用所选论文的摘要、笔记、卡片及已有对比，需要正文证据时仍按页读取。
- 新增 arXiv 文献发现与 Atom 关键词订阅：查看最新二十篇结果，确认后入库，显示库内重复项与同名候选，手动刷新与标记检查时间。
- 关联发现为新论文补充旧库候选；生成完成前不标记已分析，取消不消耗增量分析状态。
- 普通论文讨论默认只读，保存笔记由用户明确触发。

## 数据与接口

- 原有 `papers/`、笔记、批注、卡片、对话和对比文件格式保持兼容。
- 新文件：`.paperdesk/research.json`，包含 `schemaVersion: 1`、`topics` 和 `subscriptions`。
- 专题只保存论文 ID，不复制 PDF。专题与订阅修改要求客户端提交读取时的 `baseHash`；过期版本返回 HTTP 409。同一 Host 的修改按库串行执行。
- `/research`：读取、新增/更新和删除专题；`/research/prompt`：构造限于所选资料的讨论上下文。
- `/research/discover`：arXiv 检索；`/research/subscriptions` 和 `/research/subscriptions/check`：订阅及已读检查时间。
- 图片使用宿主标准内容块 `{ type: 'image', mediaType: 'image/jpeg', data, name }`，由现有 `session.prompt` 提交，不把图片编码进提示词文字。

## 验证

```bash
npm run typecheck
npm run build
npm run test:regression
npm run smoke
git diff --check
```

针对性回归覆盖摘要/笔记/正文查询、过滤回归、新旧论文关联范围和预算、专题持久化与过期写入、选定资料范围、Atom 解析与去重，以及图片内容块实际到达会话提交接口。宿主替身仅用于接口回归，不视为真实模型验收。

产品验收使用隔离 DSH profile 和论文库，报告与原始证据保存在 `.acceptances/`；界面比较记录在 `design-qa.md`。真实验收结论以当次报告为准。

## 已知边界

- 需要支持图片输入的当前会话模型。图片最长边为 2000px，极小公式或密集图表可能仍看不清；应核对原页，不能把模型答案当作原文。
- 真实模型验收包含无文字层的合成页。模型能使用图像信息，但曾将清晰的字母 B 误读为 E；该反例保留在验收报告，不作为精确 OCR 通过。另一个真实 TRIO 公式页任务能正确区分奖励公式，不能据此推断所有图片均可准确识别。
- 当前为每回答独立的页级引用与来源预览，不包含段落坐标定位或结论正确性的自动认证。
- 正文检索依赖已存在的提取缓存；不增加 OCR 或整库结构化解析。
- arXiv 订阅按需刷新，不提供后台定时追踪或任意 RSS URL；网络服务不可达会显示错误。
- 关联候选使用文本词项重叠排序，从旧库选取最多十二篇；它是受限候选集合，不保证全库关联召回。
- 专题冲突检查不构成跨设备分布式事务，应避免网盘两端同时编辑同一文件。
- 不接入 Zotero，不发布 npm 包；本次交付目标为验证后提交并推送 Git 仓库。
