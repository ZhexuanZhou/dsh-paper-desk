# v0.4.4

- 修正 PDF 链接热区：使用当前 pdf.js 的 convertToViewportPoint 转换矩形两个角，再归一到页面。正确处理纵轴翻转、缩放、页面旋转、裁切和 UserUnit；坐标无效或缺少转换时不创建错误热区。页内与外部链接共用转换。
- 导入时自动用当前配置的 LLM 补全空的摘要、关键词、标签。原逻辑只生成标签，且摘要为空时跳过；现在一次请求依据标题、已有摘要及前 4 页最多 7000 字符处理三个字段。优先忠实提取作者摘要，未提供时仅依据节选生成简短概述，不编造实验结果。已有字段保持不变。
- 上传、文件路径、链接、收件箱与 Agent 导入共用该补全流程。LLM 不可用、输出无效或超时不阻断 PDF 保存；上传/链接导入显示警告，后台记录失败，可从信息页“用 LLM 补全空项”重试。未能生成摘要时保留空值，不用标题伪造摘要。既有同文件去重不改写旧论文。
- 信息页增加补全空项操作，编辑未保存时禁用。生成结束后在共享元数据写入队列中重新检查空项，避免晚到的 LLM 结果覆盖用户编辑。笔记、卡片及原 PDF 不被自动修改。

- 元数据模型请求采用宿主的内容块数组协议；显式处理流的 error/aborted 结束事件，不将失败流中的部分 JSON 当作成功。安全日志包含模型路由与错误码，不输出凭据或正文。
- 修正信息页服务端更新后的草稿同步：用当前表单、先前服务端值和新值做三方合并。未编辑字段接收 LLM 结果，真正手工修改的字段保留，不会把干净表单误判未保存。
- 按论文库记住上次打开的论文，离开插件再返回或刷新时恢复。恢复完成前不抢选首篇；失效的论文 ID 清除后安全回退，临时请求失败保留记忆。存储不可用时仍可阅读；本地记忆不写入论文数据，也不在不同论文库间串用。

验证：类型检查、构建、PDF 链接几何专项、元数据专项、既有回归与冒烟。链接专项使用安装的真实 pdf.js，覆盖六种 scale、0/90/180/270 度、反向角点、裁切、UserUnit=2、越界/无效输入，并对原 TRIO PDF 复核。元数据专项覆盖空摘要触发、已有值保护、失败可见、持久化、并发手工修改和旧标签回调兼容。真实 UI 验收沿用隔离 DSH profile，实际模型调用与 mock 单元边界分开记录。

实际验证命令：`npm run typecheck`、`npm run build`、`npm run test:pdf-links -- <原始PDF路径>`、`npm run test:import-metadata`、`npm run test:ui-state`、`npm run test:regression`、`npm run smoke`。专项分别通过 1374 项（含原 TRIO PDF）、28 项和 14 项检查；既有回归 67 项、冒烟 33 项通过。真实上传与既有字段保护由实际配置的模型验证，UI 检查另覆盖跨插件返回、刷新恢复与失效记录回退。
