# v0.4.7

- 修正实际发布包中的 Markdown 层级：打包脚本曾给 esbuild 输出的每行代码加制表符，连 Marked 内部模板字符串的换行分隔内容也被改写。现在原样保留构建输出，再放入模块加载器。原回答后续标题不再被吞进前面的列表，正常嵌套列表仍保留层级。
- 数学公式改用 Marked 的行内和块级扩展解析，支持比较符号以及 `$…$`、`$$…$$`、`\(…\)`、独立的 `\[…\]`。移除全文代码/数学占位替换，由解析器处理代码跨度、围栏和列表；代码中的美元符号、普通金额与占位符形状的原文保持字面内容。
- 保留 KaTeX 生成的原生 MathML，使用插件自己的外层类名及数学字体，避免宿主的 KaTeX HTML 样式干扰。数学元素本体不滚动；长公式在外层容器内横向滚动，后续段落保持正文基线。无效或不完整公式保留转义后的原文。
- AI 助读、卡片和笔记共用渲染器。修正显示，不改写既有回答、卡片或笔记原文。HTML 转义及危险链接过滤保持有效。

验证命令：

```sh
npm run typecheck
npm run build
npm run test:markdown
npm run test:markdown -- <原始回答Markdown路径>
npm run test:regression
```

类型检查和构建通过。Markdown 专项默认 57 项；加入本地原始回答后 60 项通过，既有回归 67 项通过。专项在 Node VM 中实际执行发布模块的 factory，读取其原有渲染函数，并逐项对比源码与发布包的正文、笔记分节和目录输出；不会把只测源码的结果作为发布包正确性的证明。

真实界面验收 3/3 通过，6 份所需证据齐全。原始回答的标题从约 120px 累计缩进恢复到正文基线，两处 `s>1` 正常排版；边界稿在助读、卡片、笔记三处验证，实际隔离保存的卡片及笔记与原稿比对一致。400px 下长公式在自身容器内可横向滚动，600px 下正文与操作可读。本地界面已刷新到 0.4.7，原始对话文件哈希未变；本轮没有重新调用模型生成原回答。验收服务与专用标签已清理。
