# v0.5.0

本版把笔记、卡片从只追加的记录开放为可以通过对话编辑、重组和恢复的文档。

- 笔记支持整篇重写和局部唯一原文替换。先读取完整内容及版本，再修改原笔记；不会把重整要求替换成新增带日期条目或另建卡片。
- 卡片支持单次批量创建、更新、删除和排序。合并、拆分通过一批操作提交，先验证整批，再原子写入；其中一项无效时不会留下半批修改。
- 所有正常笔记/卡片写入保存修改前快照，覆盖 Agent、手动编辑/删除、卡片合并及笔记冲突副本采用。恢复前保存当前版本，可反向恢复。
- “笔记”“卡片”页新增版本历史：列出时间及操作、预览原内容、恢复、撤销本次恢复。恢复整个卡片集合，不把单卡历史混用为集合历史。未保存笔记草稿会阻止恢复。
- 对话面板使用统一会话菜单、新建按钮及删除确认弹窗，提供查看笔记/卡片导航；输入区自动增高，生成时可编辑下一条草稿；长表格/公式独立滚动，跳转最新不遮住正文。
- 普通讨论只读；明确要求编辑、重组、删除、恢复即授权指定范围内操作。失败与部分完成须明确报告，不虚报保存成功。

新增工具：`paper_notes_write`、`paper_notes_replace`、`paper_cards_edit`、`paper_history_list/read/restore`。笔记读取支持分页，卡片读取返回与内容对应的集合 hash。重写、批量重组及恢复要求版本 token；卡片单项更新/删除校验 updatedAt。

版本位于 `.paperdesk/history/<paperId>/<notes|cards>/`，保存修改前的原始 UTF-8 内容及 hash。恢复后再次修改也会继续记录；相同内容的无操作恢复不会制造重复版本。未被记录的升级前历史无法重建，历史不自动清理。Host 内串行化与写前检查不提供跨设备分布式事务保证。

历史专项含真实工具执行、SDK 无损 JSON 和输出 schema 检查、HTTP 预览/恢复、精确恢复与反向恢复、并发追加、过期版本、批量失败不半写、快照写失败不修改原内容；异常旧卡片预览有独立检查。类型检查和构建通过，自动化共 259 项通过（历史编辑/宿主输出契约 44、异常预览 8、既有 Agent 操作 18、smoke 33、回归 67、发布 Markdown 57、草稿 25、过程分组 7）。真实模型及界面 5/5 项通过：原笔记去重重写、卡片合并拆分、通过对话恢复两类版本、界面预览/恢复/撤销、对话管理与600px面板。笔记和卡片均按原内容比对；手动保存/删除也留下了完整快照。

真实卡片重组曾出现“已落盘但输出不满足无损 JSON”的宿主错误，原因是返回了 context:undefined。已改为省略不存在的字段，并使用宿主实际 snapshotJsonValue/输出 schema/render 检查，补充真实成功调用；修复前记录保留为失败沿革，不作为成功证据。模型部分未针对极长公式做专门生成和拖动，相关渲染回归检查复用已有覆盖，不夸称新执行。
