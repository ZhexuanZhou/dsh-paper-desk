# 知页 · 论文助手 1.1.0

研究专题改为预先定义问题和资料范围的研读工作台。创建后自动开始解读，主区展示结果，右侧继续讨论；研究问题和文献管理移入专题设置。

## 变化

- 通过右侧对话编辑、重写专题笔记，创建、编辑、删除或排序专题卡片，以及更新专题解读。普通问答保持只读，明确要求编辑时才写入。
- 专题卡片保存在专题里，并关联来源论文，不会默认复制到单篇论文卡片。
- 解读、笔记、卡片集合分别保留修改前版本。可以预览和恢复，恢复不会回退研究问题、关联文献和专题生命周期，也不改变全局论文阅读状态。版本文件不自动清理。
- 移除专题关联文献的 30 篇硬限制，专题资料与本次讨论范围分开选择。超出应用 60000 字符资料预算时提示缩小本次范围，不静默截掉所选论文。每篇资料仍使用明确说明的节选，不能等同于已读全文。
- 初次生成与对话编辑分开处理：生成阶段只读资料并输出正文，由页面保存；右侧明确要求修改时才通过 Agent 编辑，避免同一轮由两处保存而产生冲突。
- 创建专题自动提交一次解读任务。流式结果展示后再保存；切换页面功能可继续，重新打开已有结果不会自动重复调用模型。改变问题或范围时保留旧结果并提示更新。
- PDF/arXiv 链接支持每行一条批量导入，按顺序处理，逐项反馈成功、重复和失败，并支持单项或全部失败项重试。
- 阅读状态移到标题操作区的独立菜单。实际保存笔记、卡片或加入进行中的专题，仅把未读自动改为在读；已读和归档保持原状。结束专题时可选择将关联论文批量标为已读，归档除外。
- 前后台版本不匹配时，专题页提示先在插件管理器中重新加载，避免生成结果后才发现后台不支持保存。

## 存储与边界

保留既有论文库目录和安装标识。多设备使用时请统一更新到 1.1；旧版专题编辑器不保留新增的解读、专题卡片和状态字段，不应再用旧版编辑已升级的专题。专题与卡片在 `.paperdesk/research.json` 中，专题文档历史在 `.paperdesk/topic-history/` 中。首次修改旧文档会保留当前内容，不能重建启用版本记录以前的编辑。

专题编辑使用读取时的文档哈希，单个 Host 内串行保存并在写入前检查外部变更；检测到冲突会拒绝覆盖。这不等同于跨设备分布式事务。专题文档最多 60000 字符笔记、100000 字符解读，单张卡片正文最多 20000 字符。

刷新或关闭整个页面会中断前端对运行任务的跟踪，不承诺自动续跑解读或导入队列。已保存内容不受影响，重新打开不会悄悄重复调用模型。模型结果、引用页码与建议仍需对照原文核查。

## 验证

类型检查和构建通过，18 套自动检查共 780 项通过。新增专项覆盖批量队列、初始解读生命周期、专题编辑与恢复、真实 SDK 返回契约、HTTP 冲突保护和关联范围；既有 PDF、元数据、笔记卡片及 Markdown 检查保留。

隔离合成库已实测自动解读、重新打开、右侧 Agent 修改三个专题文档及来源卡片、笔记/卡片历史恢复、结束与重开专题。初次生成曾触发模型和页面重复保存；修复后模型仅只读资料，最终报告与保存的 Markdown 完全一致。重新打开结果没有重复提交。右侧明确要求编辑时会实际落盘，未写到单篇论文卡片。

文献增减与本次讨论范围分别验证：加入第三篇后仍保留原两篇讨论范围，移除后恢复两篇。35 篇专题中选定两篇后，真实问答只读取这两篇的第 1 页，没有写入文档。

批量队列实测已有记录、错误行和单项重试，成功记录与原输入均保留；公开 W3C 测试 PDF 通过真实链接成功入库，再导入提示重复。元数据补全提示空项未完全补齐，不将其称为完整补全成功。关闭导入窗口后可继续完成并通知。

笔记存在未保存草稿时，版本历史、结束专题和更新解读被禁用；“放弃修改”恢复本地预览并重新启用历史，不写文档。未形成“导入完成与用户开始编辑草稿恰好重叠”的真实 UI 前提，该补充边界不声明已实测；生产导航保护另通过可复现异步时序检查。

本地插件通过 Harness 插件管理器关闭再开启后，前端与后台均显示 1.1.0，研究专题页正常加载。能力通过根据源码中的检查条件与页面结果推断，未声称直接读取状态字段。真实论文库未执行内容编辑或模型任务；重载前缺少可比较的论文选择信号，不宣称本轮实测了选择保持。
